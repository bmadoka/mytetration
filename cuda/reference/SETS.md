# 대조 세트와 판정 규칙 (고정)

세트와 판정 규칙은 **새 구현(CUDA)을 처음 돌리기 전에** 정했다.
그 뒤에 바꾼 것은 하나다(새 구현 첫 실행 뒤): §3 (0)에서 NaN 성분끼리는 비트 패턴(부호·payload)을 보지 않기로 했다. 이유: NumPy의 복소 덧셈이 NaN+NaN에서 SIMD 레인에 따라 어느 쪽 NaN 비트를 줄지가 달라(같은 입력 비트에서 픽셀 (0,1)은 둘째, (0,2)는 첫째 피연산자), 값이 아닌 비트 무늬를 맞추는 일이라서다. 영향 범위: 합성 특수 격자 시험(`test_special_grid_nan_inf`, 좌표에 NaN·inf)뿐이다. 13세트의 c에는 NaN이 없고, GPU 격자 c가 13세트 전 픽셀에서 비트까지 같다는 시험(`test_gpu_grid_bit_identical`)은 그대로 엄격하다. 커널 쪽에서는 NaN 부호에 기대던 유일한 곳(cexp(−inf, NaN)의 0 부호)을 UCRT처럼 +0으로 고쳤다.
세트의 단일 출처: `reference/sets.py` (값은 원본 상수 줄에 그대로 쓰는 리터럴 문자열).

## 3. 맵 판정과 반올림 경계 증명

- 맵 비교: 세트마다 새 구현 맵 vs 원본 계산 맵, 픽셀 단위. 불일치 수·비율을 적는다(상한 없음).
- 증명 대상: 불일치 픽셀 **전부** + 일치 픽셀 표본 200개.
- **일치 표본 규칙**: 일치 픽셀의 평탄 번호 `i*ny + j`(행 우선, i = x 번호)를 오름차순으로 늘어놓은 목록을 M, 개수를 N이라 할 때
  `step = max(1, N // 200)`, `offset = zlib.crc32(세트 이름 UTF-8) % step`, 표본 = `M[offset::step]`의 앞 200개(N < 200이면 일치 픽셀 전부).
- 새 구현의 궤적: `mytet_cuda/kernel.cu`를 `-DTET_RECORD`로 컴파일한 `tet_record`(같은 `tet_pixel`·`tet_cpow`에 기록만 더함)로 z₀…z_K와 멈춤 번호 K를 꺼낸다.
  - (0) z₀ = c 가 원본 식 `x[:, np.newaxis] + 1j * y[np.newaxis, :]`의 c와 비트까지 같다. 단 두 쪽 성분이 모두 NaN이면 같다고 본다(머리말 참고).
  - (i) 기록 일치: 기록 실행의 판정·K = 제품 커널(`tet_map_rows`, iters 출력)의 판정·K. 그리고 제품 커널의 맵 = iters 없이 돌린 제품 맵.
  - (ii) 한 걸음 일치: 모든 k < K에서 `w = np.complex128(c) ** np.complex128(z_k)`(NumPy 스칼라)와 z_{k+1} 비교.
    - 실수부·허수부마다 종류(유한/inf/NaN)가 같아야 한다.
    - NumPy 결과의 두 성분이 모두 유한이면 `|z_{k+1} − w| ≤ τ·|w|` (|·| = 복소수 크기 `np.abs`). τ = 64·2⁻⁵³·(1 + |z_k|·|log c|), |log c| = `np.abs(np.log(np.complex128(c)))`. |log c|가 유한하지 않으면(c = 0) τ = 64·2⁻⁵³.
    - 한 성분이 유한하지 않으면(예: `inf+0j`) 남은 유한 성분은 따로 `|차이| ≤ τ·|그 성분|`이어야 한다(그 성분이 0이면 같아야 함).
    - 성분이 비트까지 같으면(부호 있는 0 포함) τ와 관계없이 통과. τ가 NaN이면(z_k가 NaN) 비트 같음만 통과.
  - (iii) 판정 재생: m = 1…K 차례로 `np.abs(z_m) > escape_radius`(NaN이면 False)를 적용해 처음 참인 m이 K이고(발산) 그 전엔 없어야 한다. 커널이 수렴이라 했으면 K = max_iter이고 어느 m에서도 참이 아니어야 한다.
- 불일치 픽셀 하나라도 (0)~(iii)을 못 통과하면 결함(고친다).

## 4. 한 걸음 시험 (특수 경우)

- 입력: 아래 값 목록 V의 4중 곱(a.re, a.im, b.re, b.im) 전부 + 13세트 격자에서 고른 c와 그 원본 궤적의 z.
  V = {0, −0, 1, −1, 2, −2, 3, 0.5, −0.5, 0.25, 3.7, −3.7, 99, 100, 101, −101, 709, 710, 1e10, −1e10, 1e20, 1e300, −1e300, 1e−300, 5e−324, inf, −inf, NaN}
  → 밑 0(±0 부호 조합) · 정수 지수 −1·1·2·3·99·100(100은 정수 분기 밖) · 지수 0 · 음의 실수 밑(허수부 +0/−0) · inf로 넘치는 입력(2^1e10, (2+2i)^710 등) · NaN/inf 섞인 입력이 모두 들어간다. 이 목록이 필수 입력을 다 덮는지 시험이 확인한다.
- 비교: 새 구현 = `tet_onestep`(커널과 같은 `tet_cpow`·`tet_clog`), 기준 = NumPy 스칼라 `np.complex128(a) ** np.complex128(b)`.
- 판정: 성분마다 종류 같음 · 유한이면 위 τ(z_k 대신 b, c 대신 a) 안 · `abs(w) > r`이 r ∈ {1e3, 1e6, 1e10}에서 같음.
- 덧붙여 `np.abs`도 같은 방식으로: 새 구현 `tet_abs`와 NumPy `np.abs`가 비트까지 같아야 한다(커널의 발산 판정 = 원본 판정).

## 5. 시험용 계산기 대조

- `tester/calc.py`의 전체 계산이 13세트 모두에서 원본 계산 맵과 바이트까지 같아야 한다.
- 일부 행 경로(x 행 i = 0, 32, 64, …)가 같은 행의 전체 계산과 바이트까지 같아야 한다(13세트).

## 6. 속도 측정 규칙 (단계 B, 측정 전에 고정)

- 판정 세트: D1, Z1 (각 n=500). 비율 = 원본 시간 ÷ 새 구현 시간 ≥ 100.
- 구간: 매개변수를 넣어 맵 함수를 부른 때 → bool 맵 전체가 호스트 메모리에 온 때(GPU 동기화·전송 포함). 새 구현 = `mytet_cuda.divergence_map(...)`. 원본 = 기준 장치 사본의 `compute_tetration_divergence` 호출(그 함수 소스를 사본에서 그대로 꺼내 실행). 측정 스크립트는 이 묶음에 없다. 결과 숫자는 README_CUDA.md에 있다.
- 반복: 새 구현 4회(첫 회 버림, 나머지 중앙값), 원본 2회(두 번째 값, 둘 다 기록). 반복 r(0부터)마다 x0 += r × 1e−9 × eps, 맵 sha256 기록.
- 첫 실행(프로세스 시작·import·첫 컴파일 포함)은 따로 적는다. 끝-끝(그림 저장 포함, Agg, `plt.show` 없음)도 적는다.
- 4K: n = 3840, 같은 D1·Z1. 원본 전체가 60분을 넘을 것으로 보이면(D1 n=500 원본 실측 약 120초 × 픽셀 59배 ≈ 2시간 → 넘는다) x 행 i = 0, 32, 64, …, 3808(120행)만 시험용 계산기로 돌리고 ×32를 «추정»으로 적는다.
- 표에 GPU 이름·정밀도(float64)·측정 시각 `nvidia-smi` 출력을 함께 적는다.
